vmpx reference

Rust workspace, edition 2024, rust-version = "1.88", MIT. unsafe_code = "forbid" workspace-wide.

Evidence-driven static-analysis toolkit for VMProtect-protected Windows PE files. The CLI binary is named vmpx (package vmpx-cli); the logic lives in eight library crates. Everything is static: the input is parsed and analyzed, never executed.

Build & run

cargo build --release

Builds the workspace (members: vmpx-cli, vmpx-detect, vmpx-disasm, vmpx-pe, vmpx-rebuild, vmpx-recompile, vmpx-unpack, vmpx-vm, vmpx-vmlift).

cargo run -p vmpx-cli -- --help

Runs the vmpx binary through cargo and prints the clap help (subcommand list). --version is also enabled. Any subcommand follows the --, for example cargo run -p vmpx-cli -- detect sample.exe --json.

Large-fixture tests
The CLI integration tests read an optional VMPX_FIXTURE_DIR environment variable (default directory testfilevmp) for large real-world fixtures that are not distributed with the repository; those regressions are the ignored tests in crates/vmpx-cli/tests/clean_command.rs.

Pipeline at a glance

The clean command chains the libraries in this order (as implemented in crates/vmpx-cli/src/clean.rs):

  • vmpx-detect classifies the input and its layout.
  • vmpx-unpack restores packed sections when the layout is PackedVirtualSections; otherwise the input is analyzed as-is.
  • vmpx-vm discovers VM entries, recovers bootstrap and handler codecs, and symbolically executes VM paths to native exit states.
  • vmpx-vmlift collects the path effects and builds replacements; vmpx-recompile lowers them to x86-64.
  • vmpx-rebuild relayouts to a conventional PE, validates it for the loader, and (when replacements exist) appends a section and redirects entry points.

CLI commands

Source: the clap Command enum in crates/vmpx-cli/src/main.rs. Subcommand names are clap's kebab-case of the variant names. There are nine subcommands. Where --json is accepted, the output is pretty-printed JSON; otherwise a bracket-tagged text report is printed ([pe], [vmp], [vm], ...).

read-only writes files proof-gated
vmpx clean <INPUT> <OUTPUT> [--report <PATH>] [--reconstructed <PATH>] [--experimental <PATH>]proof-gated

Runs the complete proof-gated recovery pipeline and emits a clean PE only when safe.

positional
INPUT the PE to analyze; OUTPUT where the clean PE would be written.
--report PATH
Write the versioned JSON recovery report (CleanReport, schema_version 1) even when the proof gate refuses output.
--reconstructed PATH
Also write the conventional-layout image of the unpacked analysis image. It is loadable and structurally valid but not devirtualized: protector sections and VM handlers remain. It is written (and reparsed from disk) before the gate decision, so it is produced even when the gate refuses.
--experimental PATH
Write the reintegrated image to PATH regardless of the proof gate, with a warning on stderr. The report gains experimental: bool. This does not relax the gate: the sound OUTPUT is still written only when the proof gate clears.
proof gate
The report carries a blockers list; ready_to_write is true only when it is empty. If blockers remain, clean prints each as [clean] blocker: ..., writes the report if requested, and exits with an error (clean proof gate refused ...; output ... was not written). No OUTPUT file is created.
protected input
For an input with VMProtect evidence the code unconditionally adds four blockers: original module entry point not recovered; application import set not proven independently reconstructed; native code reintegration has not produced a devirtualized replacement image; VMProtect sections remain referenced by unresolved paths. Further blockers are added per case (for example a non-DLL header entry: "generic finite input-domain recovery for an executable entry is not implemented"; unresolved TLS VM entries; incomplete entry path recovery).
clean input
If detection yields NoStrongEvidence and the layout is ConventionalFile, the run is a "verified no-op": the gate clears and OUTPUT is a byte-for-byte copy of INPUT, reparsed from disk. NoStrongEvidence with a non-conventional layout adds a blocker.
safety checks
Refuses to overwrite the input (directly or via path alias), refuses if OUTPUT already exists, and refuses if --report or --reconstructed alias the input, output, or each other.
emits
Text lines [clean] (protection, layout, vm_entries, routines, blockers), [decode] per recovered path, [layout] (loader validation passed/FAILED), [verify], [report].
vmpx info <INPUT> [--json]read-only

Inspects a PE-family file by content, regardless of extension.

text
Tagged sections: [pe], [file], [hash] (SHA-256, uppercase hex), [headers], [sections], [directories], [imports], [exports], [tls], [exceptions], [relocations], [verify].
--json
Object with schema_version, path, sha256, and pe (a PeReport).
vmpx verify <INPUT> [--json]read-only

Structural validation without executing the input. Prints the same report as info, then exits with an error (structural verification reported diagnostics) if the report contains any diagnostics.

vmpx compare <LEFT> <RIGHT> [--json]read-only

Research-only structural comparison; "never used as recovery input". Compares file size, PE kind, machine, image base, entry point, size of image, per-section name / virtual geometry / raw geometry / characteristics, data directories, and import / export / TLS-callback / exception-function counts.

text
[compare] lines plus one line per modeled difference, or "no modeled structural differences". Differences do not change the exit status.
--json
Object with schema_version, left and right file summaries (path, sha256, counts), and differences (strings).
vmpx unpack <INPUT> <OUTPUT> [--report <PATH>] [--conventional <PATH>]writes files

Recovers VMProtect-packed sections into an explicit RVA-layout analysis image.

OUTPUT
The RVA-layout analysis image (not loadable by the Windows loader). Refuses to overwrite the input, directly or via alias. The written file is reparsed from disk.
--report PATH
Versioned JSON UnpackReport (packer table, per-block sizes, warnings, in_memory_reparsed, disk_reparsed).
--conventional PATH
Also write the image in conventional file layout (loadable by the Windows loader) after running loader validation; must not alias input, output, or report.
emits
[unpack] lines: packer-table kind and file offset, one line per block (src, dst, decompressed size / capacity, section virtual size), warnings, loader-validation counts and layout summary when --conventional is used, then [verify] and [report].
vmpx detect <INPUT> [--json]read-only

Profiles VMProtect evidence and packed/mapped layout. JSON is the full ProtectionReport.

text
[vmp] verdict=... confidence=... layout=..., one weighted evidence line per finding (+weight id: statement), one [region] line per executable section (RVA, size, entropy, whether it owns the entry point), and warnings.
vmpx vm-list <INPUT> [--json] [--no-scan]read-only

Discovers evidence-scored VM entry stubs and mutated bootstrap profiles.

--no-scan
Restrict discovery to the PE entry point and TLS callbacks (sets scan_executable_stubs = false); otherwise executable sections are also scanned for entry-stub candidates.
text
[vm] summary (entries grouped into bootstrap profiles, stub candidates checked), one line per instance, one line per entry (entry, source, reachability, confidence, seed, call, bootstrap), diagnostics.
--json
Full VmDiscoveryReport, including rejected_roots.
vmpx imports <INPUT> [--json]read-only

Inventories imports and direct native RIP-relative IAT references.

method
Counts modules, named vs. ordinal symbols, and duplicate identity groups; then runs two resynchronizing decode scans for RIP-relative references to exact IAT slots: one over exception-table function ranges, one over the remaining executable bytes (each given a 30,000,000 candidate-decode budget). Each reference is tagged exception_range_resync_candidate or executable_resync_candidate.
emits
[imports] lines and one instruction_rva -> slot (module!symbol; discovery) line per reference; JSON is ImportAnalysis (schema_version 1).
warnings
Always includes: absence of a direct reference does not prove an import unused; duplicates are preserved as evidence; exception metadata alone does not prove reachability; independent-start findings are decoded candidates, not proven-reachable. Truncation warnings are added when a scan hits its budget.
vmpx oep <INPUT> [--json]read-only

Ranks module-entry evidence without assuming the protected header entry is original.

method
Runs VM discovery restricted to loader roots (no executable scan). If the header entry is a discovered VM entry, header_entry_assessment is protector_vm_entry with its confidence and evidence; otherwise unresolved. TLS roots rejected as VM entries are listed as native_tls_candidates.
limitation
recovered_entry is always None in the current code. The warnings state that no original native entry is emitted until a VM-exit/native-transition path is decoded, and that the workspace has no unprotected semantic oracle.
emits
[oep] lines; JSON is OepAnalysis (schema_version 1).

vmpx-clibin: vmpx

The command-line front end. Binary target vmpx (src/main.rs) with an internal clean module (src/clean.rs) that implements the proof-gated pipeline and the CleanReport schema. It depends on all other library crates plus clap, serde, serde_json, sha2, and anyhow. It exposes no library API.

Derived from the sources under crates/*/src: subcommands from the clap Command enum, crate surfaces from each lib.rs.

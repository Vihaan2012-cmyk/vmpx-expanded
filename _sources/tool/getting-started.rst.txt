Getting Started
===============

Requirements
------------

* A Rust toolchain of version 1.88 or newer (the workspace uses edition 2024).
* No native dependencies for the default build. The optional VTIL optimizer
  bridge (:doc:`crates/vtil-sys`) needs a C++ toolchain and a prebuilt VTIL
  library, and is off by default.
* Windows is the reference platform for running the egui front-end
  (:doc:`ui`); the command-line tool and all libraries build wherever Rust
  does, because they only parse files.

Building
--------

Clone the repository and build the workspace:

.. code-block:: console

    $ git clone https://github.com/Vihaan2012-cmyk/vmpx-expanded.git
    $ cd vmpx-expanded
    $ cargo build --release

The workspace members are ``vmpx-cli``, ``vmpx-detect``, ``vmpx-disasm``,
``vmpx-pe``, ``vmpx-rebuild``, ``vmpx-recompile``, ``vmpx-ui``,
``vmpx-unpack``, ``vmpx-vm``, ``vmpx-vmlift`` and ``vmpx-vtil-sys``. The
resulting binary is ``target/release/vmpx`` (``vmpx.exe`` on Windows).

Running through cargo
~~~~~~~~~~~~~~~~~~~~~

Any subcommand can be run without installing the binary. Arguments after the
``--`` are passed to vmpx:

.. code-block:: console

    $ cargo run -p vmpx-cli -- --help
    $ cargo run -p vmpx-cli -- detect sample.dll --json

``--help`` prints the clap subcommand list; ``--version`` is also enabled.

Your first analysis
-------------------

The recommended order mirrors the pipeline. Start read-only, then move to the
commands that write files.

#. Check that the file is a PE vmpx can parse, and look at its structure:

   .. code-block:: console

       $ vmpx info sample.dll

#. Ask whether it looks protected, and how it is laid out on disk:

   .. code-block:: console

       $ vmpx detect sample.dll

   The verdict is ``NoStrongEvidence``, ``Suspicious`` or
   ``VmprotectLikely``. The layout is ``ConventionalFile``,
   ``PackedVirtualSections``, ``RvaMappedAnalysisImage`` or ``Ambiguous``. See
   :doc:`cli/detect`.

#. If the layout is ``PackedVirtualSections``, recover the packed sections:

   .. code-block:: console

       $ vmpx unpack sample.dll sample.analysis --report unpack.json --conventional sample.loadable.dll

   ``sample.analysis`` is an RVA-layout analysis image. ``sample.loadable.dll``
   is the same content in conventional file layout, loadable by the Windows
   loader but not devirtualized. See :doc:`cli/unpack`.

#. List the virtualized entry points:

   .. code-block:: console

       $ vmpx vm-list sample.dll

   See :doc:`cli/vm-list`.

#. Run the full pipeline:

   .. code-block:: console

       $ vmpx clean sample.dll sample.clean.dll --report clean.json

   For a protected input this will, today, refuse to write ``sample.clean.dll``
   and print the blockers that remain. The report is still written. See
   :doc:`cli/clean` and :doc:`soundness`.

#. To inspect what the machinery would produce regardless of the gate:

   .. code-block:: console

       $ vmpx clean sample.dll sample.clean.dll --report clean.json --experimental sample.experimental.dll

   .. warning::

       ``--experimental`` output is unverified. It is written for inspection
       and testing only, and may be confidently wrong. See
       :ref:`experimental-output`.

Workspace layout
----------------

.. code-block:: text

    crates/
      vmpx-pe/         strict PE/COFF parser and address model
      vmpx-detect/     VMProtect evidence scoring, image-layout classification
      vmpx-disasm/     x86-64 decode, CFG, IAT references, dispatch proofs
      vmpx-unpack/     PACKER_INFO location, LZMA restore, analysis image
      vmpx-vm/         VM discovery, codecs, symbolic execution, OEP
      vmpx-vmlift/     lifting, readiness audit, live-in inference, equivalence
      vmpx-recompile/  conservative x86-64 code generation
      vmpx-rebuild/    guarded PE rewriting, reintegration, imports
      vmpx-cli/        the vmpx binary and the proof-gated clean pipeline
      vmpx-ui/         egui front-end driving the CLI
      vmpx-vtil-sys/   feature-gated FFI binding to the VTIL optimizer bridge
    native/
      vtil-bridge/     C++ bridge around VTIL's optimizer
    docs/
      superpowers/     design specs and implementation plans
      site/            these Sphinx sources

Building this documentation
---------------------------

The documentation is generated by `Sphinx <https://www.sphinx-doc.org/>`_ with
the ``sphinx_rtd_theme`` theme:

.. code-block:: console

    $ pip install sphinx sphinx_rtd_theme
    $ cd docs/site
    $ python -m sphinx -b html . _build/html

Large-fixture tests
-------------------

The CLI integration tests read an optional ``VMPX_FIXTURE_DIR`` environment
variable (default directory ``testfilevmp``) for large real-world fixtures that
are not distributed with the repository. Those regressions are the ignored
tests in ``crates/vmpx-cli/tests/clean_command.rs``. See :doc:`testing`.

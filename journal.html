Origin & verdict

The user asked to scan github.com/skyboundfs/vmpx for malware. Cloned and inspected statically. Verdict: no malware — a VMProtect static-analysis / devirtualization toolkit in Rust (~42k LOC). unsafe forbidden workspace-wide, no build.rs, no network / process / dynamic-loading / crypto-exfil surface. The one scare — serde_json depending on zmij instead of ryu — is legitimate: serde_json migrated its float formatting from Ryū to Żmij. The native C++ VTIL bridge is a clean FFI wrapper.

Goal & strategy

  • Goal: carry the pipeline to clean, behavior-preserving ("reversible") devirtualized output, as provable milestones.
  • "Reversible" = behavior-reversible, not bit-reversible. Virtualization is lossy; we rebuild semantics, not original bytes.
  • Strategy: a mix of A (soundness-first) and C (hybrid/decomposed). The sound, proof-gated path is the default; an explicit, labeled --experimental mode is scaffolding to test the machinery early.
  • Validation: synthetic fixtures in CI + the user's local VMProtect samples out-of-band (never committed). Universal "any binary" correctness stays aspirational.
  • Anti-debug: analysis is fully static, so runtime anti-debug never fires against us. Output policy is user-selectable — faithful (default, equivalent) vs --neutralize (debuggable, deliberately non-equivalent).
  • Fully static — no dynamic dumper. UI: egui/eframe, folded into current work.

What "recovered" means here
Without a protected corpus in CI, "recovered" means the result passed synthetic verification and review, never a bare assertion. Recovery is deliberately strict: where soundness is not provable, the tool refuses and keeps the blocker rather than guessing. Real-sample behavior is checked out-of-band.

Task 4b · finite-domain branching recovery + EXE entrycomplete

A spike concluded that the general branching case is undecidable, so Task 4b implements a sound decidable subset and refuses everything else.

  • 8-bit slices and vm_flags_add affine compares (cmp/jcc and small switch ladders).
  • 16-bit covers are verified against the exact 216 image; 32- and 64-bit covers are proven exhaustive by derivation (tests only sample, a low process gap, not a soundness one).
  • EXE-entry recovery reuses the Task 4a empty-domain path and drops the EXE blocker only on a successful recovery.
  • Refused (blocker kept): jump tables, memory-dependent targets, loops, nested input branches, mixed widths, nor/nand, opaque intrinsics.

The Soundness Model

vmpx is a soundness-first tool. Producing some output is easy; producing output that is correct is the whole point, and the two diverge badly for a protected binary. This page defines what the tool promises, what it withholds, and what the words “recovered”, “blocker” and “experimental” mean.

Principles

Fail closed

Ambiguity is kept in a report and yields no result, rather than a guess. Many functions have a branch of the form “if I cannot prove this, return an error or a blocker”: “no unknown value is invented”, “it never guesses a missing operation”, “shape agreement alone is not sufficient”.

Static only

The input is never executed. This is a design choice with a loud consequence: runtime anti-debug and anti-tamper never fire against the analysis, because there is no process, no PEB, no timing source and no breakpoint. A dynamic dumper would be a different architecture that reintroduces the whole anti-debug problem; it is explicitly out of scope.

Behaviour, not bytes

“Reversible” means behaviour-reversible. Virtualization is lossy: original instruction encodings, function boundaries, padding and the pristine .text are destroyed. The output reproduces semantics. It will not match a hash of the unprotected original, and a disassembly diff will look nothing alike even when behaviour is identical.

“Any binary” is a direction

Correctness is proven on synthetic fixtures and empirically confirmed on local samples. Coverage is bounded by the VMProtect constructs that have been lifted and proved; outside them, the sound path refuses.

What “recovered” means

There is no protected corpus in continuous integration. “Recovered” therefore means the result passed synthetic verification and review. It does not mean a behaviour was observed on a real sample. Recovery is deliberately strict: where soundness is not provable the tool refuses and keeps a blocker.

Each recovered thing carries its own proof obligation:

Recovered item

What must hold

A VM entry

Evidence-scored at confidence 60 or more; the bootstrap yields a behaviourally valid dispatch slice under some role assignment

A handler’s semantics

A path

The decoder reached VmExit with the exact native exit state read from the terminal memory snapshot

A path family

domain_complete and all_paths_reach_vm_exit

The OEP

The path family is complete and every path resolves to one native continuation (OEP Recovery)

A function’s input domain

Structurally proven exhaustive (never sampled)

A replacement

Passes the readiness audit and compiles under ABI validation; equivalence over the recovered domain is checked by the differential verifier

An output image

Reparses, and passes validate_for_loader

Blockers and the proof gate

A blocker is a statement of a proof that does not yet exist. clean collects them in CleanReport.blockers. ready_to_write is true only if the list is empty, and the sound OUTPUT is written only then.

The verified no-op

An input classified NoStrongEvidence with a ConventionalFile layout is the only case in which clean clears its gate today. OUTPUT is a byte-for-byte copy of INPUT that has been reparsed from disk. This matters mostly as a safety property: vmpx will not “clean” a file it cannot show to be protected.

Sound output and experimental output

There are two output paths, and they never mix.

--experimental does not relax the gate. It is scaffolding so the pipeline can be exercised against real samples early, quarantined to its own path.

Known risks of experimental output:

  • it can be confidently wrong;

  • a dispatcher falls back to the original protected entry for inputs outside the recovered domain, which is only a safety net when the domain is complete;

  • an edited image interacts with any live integrity check (see Verification and Anti-Debug Policy).

Behaviour-changing modes

Two modes each weaken a guarantee. Both are off by default, labelled, and do not change the semantics of the sound OUTPUT:

--experimental

Gate-relaxed emission. Implemented on clean.

--neutralize

Anti-debug stripping. The transform is implemented as a library function; it is not yet a clean flag.

Where soundness still has gaps

The tool is explicit about its limits:

  • no protected corpus in CI, so synthetic fixtures may be unrepresentative;

  • a missed VM entry (false negative) leaves a .vmp reference, so the sound mode correctly refuses;

  • a mis-identified VM entry (false positive) must not produce a wrong replacement; confidence gating and the proof gates guard against it;

  • general per-function input-domain inference is unsolved. Only a decidable subset is implemented: 8-bit slices and add-flags covers, with jump tables, memory dependent targets, loops, nested input branches, mixed widths, nor/nand and opaque intrinsics refused;

  • output equivalence is verified over the finite recovered domain, not universally.
